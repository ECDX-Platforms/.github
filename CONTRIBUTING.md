# Contributing

Thank you for contributing to ECDX Platforms.

## Before You Start

- Search existing documentation and issues before opening a new request.
- Prefer improving an existing pattern over creating a competing one.
- Do not include credentials, customer data, personal data, or confidential information.
- For substantial changes, open an issue first so the scope and ownership are clear.

## Documentation Changes

- Keep guidance practical and concise.
- Explain important architectural decisions and trade-offs.
- Include prerequisites, validation steps, and known limitations.
- Place platform guidance in `platform-subjects` and link to runnable repositories where appropriate.

## Pull Requests

1. Create a focused branch from `main`.
2. Make the smallest coherent change.
3. Validate links, examples, and formatting locally where possible.
4. Complete the pull-request checklist.
5. Request review from the relevant subject owner.

Pull requests may be revised or declined when they duplicate existing guidance, lack an owner, or introduce avoidable security or maintenance risk.
