# Security Policy

## Reporting a Vulnerability

Do not report security vulnerabilities in public issues or pull requests.

Use GitHub's private vulnerability reporting feature for the affected repository, when available. If it is unavailable, contact the repository owners through an approved private organizational channel and include:

- affected repository, file, or component
- a clear description of the issue
- reproduction steps or proof of concept, without real secrets or customer data
- potential impact
- suggested mitigation, if known

## Sensitive Information

Never commit passwords, tokens, connection strings, certificates, customer data, or other confidential information. If sensitive information is exposed, revoke or rotate it immediately and report the incident through the organization's approved security process.

## Scope

This policy covers repositories and documentation maintained by ECDX Platforms. It does not replace Tieto's internal security incident or vulnerability-management processes; use those processes when they apply.
